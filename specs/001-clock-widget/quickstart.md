# Quickstart: 常駐デスクトップ時計ウィジェット

**Feature**: `001-clock-widget`

実装完了後、各ユーザーストーリーが動作することを手動で確認するための手順。自動テストで
検証できるのは `OkidokeiWidget.Core` のロジック(設定の読み書き・モニタ識別)のみであり、
実際の見た目・操作感は本手順で目視確認する。

## 前提条件

- Windows 11
- .NET 10 SDK (Windows Desktop ワークロード込み)
- リポジトリをクローン済みで、`src/OkidokeiWidget.App` が実装済みであること

## セットアップ

```powershell
dotnet build .\src\OkidokeiWidget.App\OkidokeiWidget.App.csproj
```

初回起動時、設定ファイルが存在しないことを確認したい場合は事前に削除する:

```powershell
Remove-Item "$env:APPDATA\OkidokeiWidget\settings.json" -ErrorAction SilentlyContinue
```

## 単体テストの実行

見た目に依存しないロジック([`data-model.md`](./data-model.md)、
[`contracts/settings-file.md`](./contracts/settings-file.md) 参照)の検証:

```powershell
dotnet test .\tests\OkidokeiWidget.Core.Tests\OkidokeiWidget.Core.Tests.csproj
```

期待結果: 全テストが成功する。特に「設定ファイルなし/不正な JSON でもデフォルト設定で
正常に読み込める」テスト (FR-018 対応) が含まれること。

## シナリオ検証

### US1: デスクトップに時計を常時表示する (P1)

```powershell
dotnet run --project .\src\OkidokeiWidget.App\OkidokeiWidget.App.csproj
```

- **期待結果**: 数秒以内にデスクトップ上に時計ウィジェットが表示され、現在時刻が 1 秒単位で
  更新され続ける (SC-001, SC-002)
- 詳細設定で日付・曜日表示を ON にすると、時刻に加えて日付・曜日が表示される
- アプリが起動している状態でもう一度起動を試み、2 つ目のプロセスが新しいウィンドウを作らずに
  そのまま終了することを確認する(二重起動防止、research.md #6、Edge Case 参照)

### US2: 見た目のカスタマイズ (P2)

- ウィジェットを右クリック→詳細設定を開く
- フォント種類・サイズ・文字色を変更し、即座にウィジェットへ反映されることを確認する
- 背景透過度スライダーを動かし、リアルタイムに背景の透け具合が変わることを確認する
- 日付/曜日表示の位置(上/下/左/右)を切り替え、時刻表示に対する配置が変わることを確認する
- アプリを終了して再起動し、変更した見た目が保持されていることを確認する (SC-003)

### US3: 配置とロック (P2)

- ロック無効の状態でウィジェットをドラッグし、位置が移動することを確認する
- 右クリックメニューから「位置ロック」を有効にし、ドラッグしても位置が変化しないことを
  確認する (SC-004)
- 右クリックメニューから「最前面表示」を切り替え、他ウィンドウの手前/背後に切り替わることを
  確認する
- 「最前面表示」を OFF にした状態でウィジェットを他のウィンドウの背後に隠し、タスクトレイの
  常駐アイコンをクリックしてウィジェットが最前面に戻ることを確認する
- タスクトレイの常駐アイコンを右クリックし、「終了」でアプリが終了することを確認する
- タスクバー・タスクトレイ・ウィンドウのアイコンが既定のものではなく専用のアイコンに
  なっていることを確認する (FR-033)

### US4: マルチモニタでの独立管理 (P3、複数モニタ環境がある場合のみ)

- 詳細設定でモニタ B の表示を OFF にし、モニタ B の表示が消え、モニタ A に影響しないことを
  確認する
- モニタ A とモニタ B でそれぞれ異なる位置に配置し、アプリを再起動して両方の位置・表示状態が
  独立して復元されることを確認する (SC-005)
- (可能であれば) モニタ B を一度取り外して再接続し、設定が保持されていることを確認する
  (research.md #2 のモニタ識別方式の検証)

### DPI 混在環境の確認 (可能であれば)

- モニタごとに異なる拡大率(例: 100%と 150%)を設定しているマルチモニタ環境、または
  ディスプレイ設定の拡大率を変更した単一モニタ環境で、フォントサイズやウィジェットの
  ウィンドウ位置が崩れずに表示されることを確認する (FR-020)

## 既知の制約の確認 (任意)

- DirectX 排他フルスクリーンモードのアプリ上ではウィジェットが隠れる場合がある
  (research.md #9 の既知の制約であり、不具合ではない)
- 背景透過度 100% の状態でも、ドラッグ・右クリックメニュー操作ができることを確認する
